# Reviewed Excel imports

Open Excel imports, select the recording office, download the current version 1 template, fill the supported sheets, choose the XLSX file, validate, review accepted values and row errors, then explicitly confirm. Cancel leaves source records unchanged. If confirmation times out, retry the same reviewed batch; do not upload it again as a new batch. A changed reference, expired review, changed permissions or altered body requires validation and review again.

The template has PARTY, VEHICLE, ROUTE, TRIP_DRAFT, CONSIGNMENT_DRAFT, STOP, CAR and EXPENSE_DRAFT sheets. Keep sheet names, version marker and headers intact. Every row has a unique workbook `row_key` (letters, digits, underscores or hyphens, up to 64 characters). Use party/route/office codes, vehicle registrations and existing trip numbers. Expense categories have permanent generated `CAT-<uuid>` codes, listed in the import workspace. Names are never silently matched. Case-insensitive duplicate codes are an ambiguity error.

Enter money, percentages and dates as TEXT in the provided text-formatted cells. Use dot decimal amounts with at most two decimals and ISO dates YYYY-MM-DD. Never enter formulas, numeric date serials or spreadsheet-calculated amounts. This protects exact decimal values from Excel rounding. A workbook is limited to 5 MB compressed, 20 MB expanded and 1,000 entered rows.

Party roles are comma-separated OWNER,CUSTOMER,BROKER,DRIVER. Party/vehicle/route creation is administrator-only and create-only. Existing records are resolved, not silently updated. The normal master commands retain existing historical records and snapshots. No offices, accounts, journal lines, opening balances or historical migration are imported.

Trip rows reference child `trip_key` values in the workbook. Stops have positive explicit positions; consignments have customer/broker codes, car counts and total quote/brokerage inputs. Cars reference a `consignment_key`; pickup/drop keys must refer to stops on that same trip. An optional return links an accessible existing trip number. Server validation uses normal draft commands and recomputes fares. Active vehicle conflicts require a row `overlap_reason` and explicit review of the preview warning before commit; dispatch still performs its own current review.

Expenses specify vehicle, optional existing `trip_code` or workbook `trip_key`, office/category/payer/cost-bearer codes, amount/date/funding source and notes. They are stored as imported drafts. Select Review expense draft to open the ordinary expense form; current claims, funding, settlement offset, optional receipt and financial confirmation are reviewed there. The import never posts an expense or creates a receipt. Confirmation is atomic and retry-safe, with a source-draft link to the newly confirmed expense.

`get_import_templates`, `validate_import`, `commit_import`, `list_import_expense_drafts` and `confirm_import_expense` are authenticated interfaces. The server repeats shape/amount/reference/office validation and binds the review token to actor, body and current resolved reference versions. The batch and all source rows commit together. Committed rows cannot be rewritten through the client. Only supported new-record commands run; ordinary clients have no table writes or private routine access.
